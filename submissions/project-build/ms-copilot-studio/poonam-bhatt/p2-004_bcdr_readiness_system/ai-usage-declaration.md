# AI Usage Declaration

# P2-004: Autonomous Multi-Agent BC/DR Readiness System

## 1. Responsible AI Overview
This document declares and details the use of Generative Artificial Intelligence (AI) during the design, configuration, and verification of the **P2-004 Autonomous Multi-Agent BC/DR Readiness System**.

AI has been used responsibly to accelerate development, outline multi-agent instructions, design test cases, and improve documentation formatting. The human developer remains fully responsible for the final architecture, tool definitions, and system testing.

---

## 2. AI Tools Used & Scope
1. **Microsoft Copilot Studio Generative Orchestration**:
   - Used to parse recurrence trigger inputs and assign slots to target variables.
   - Employed to map context objects dynamically across the six specialized connected agents (skills).
2. **LLM Assistance (Google Antigravity & ChatGPT)**:
   - Used to formulate the multi-agent instructions and structure the 2026 Modern Experience setup.
   - Utilized to create structural Markdown files and write the data conversion Python utility.
   - Assisted in generating the 25 distinct test scenarios matching the PRD test criteria.

---

## 3. Responsible AI Guardrails & Validation
To ensure compliance with critical enterprise standards, several guardrails were built into the agent's logic:

### 3.1 Non-Hallucination Guardrail (MCP Grounding)
- **Problem**: Large Language Models (LLMs) can fabricate cloud service SLA targets or disaster recovery feature support details.
- **Remediation**: The **Technical Recovery Specialist** is strictly bound to the retrieved response of the **Microsoft Learn MCP Server**. If the MCP lookup fails, the agent is prohibited from using internal parametric knowledge to make up recommendations. It must return a status of `"Technical Evidence Unavailable"` in its structured output, which triggers the Supervisor's `"Insufficient Evidence"` decision logic.

### 3.2 Bias and Decision Safety
- AI is not permitted to automatically update application architectures or delete backup databases.
- The system generates *remediation tasks* and changes the *readiness register state*, but it does not execute configurations. A human system administrator must review the Word report and execute the suggested commands.

### 3.3 Data Privacy Guardrail
- No real customer PII (Personally Identifiable Information), production database connection strings, or tenant passwords are coded into the instructions or recorded in the test report logs.
- All test scenarios use **synthetic applications** (e.g., `APP-001` to `APP-025`) and mock email addresses (`owner@novasphere.com`).

---

## 4. Verification & Validation Metrics
- All technical recommendations generated by the agent have been validated against the Microsoft Learn articles retrieved via the MCP endpoint.
- Test logs were verified to confirm that simulated network disconnects (TC-13) correctly triggered the non-hallucination workflow and blocked false compliance outputs.
- The structured output format constraint (Agent 3) was validated to ensure it produces clean, machine-readable blocks (Technology, Gaps, Recommendations, Evidence Status, Confidence) for orchestration consumption.

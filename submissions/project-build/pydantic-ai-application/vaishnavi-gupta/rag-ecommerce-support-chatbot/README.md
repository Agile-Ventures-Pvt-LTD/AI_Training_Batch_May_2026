# Project name
# PRODUCTION GRADE MARKET PLACE RAG-SUPPORT AGENT

## Business objective to make the project

- The goal of this project is to build an enterprise-grade,
production-ready Retrieval-Augmented Generation (RAG) chatbot for ShopSphere
Marketplace, a platform hosting thousands of independent business sellers.

- The chatbot must accurately ingest complex corporate guidelines—specifically focusing on
advanced business operations, fulfillment strategies, seller ratings, and profitability matrices.

- It must answer seller queries instantly while maintaining absolute deterministic safety standards,
ensuring no toxic, profane, or hallucinated outputs are surfaced to end-users.

## Technologies needed to build the project

### VALIDATION
PydanticAI
- PydanticAI is a framework that is used for validation purposes, it checks that either the input fed to the model or the output generated by it is valid or not, a valid format is already given so that validity can be checked later using that format.
- This frameworks helps reduce unnecessary errors regarding the format, validitiy etc.


### Vector Database
ChromaDB
- This is a vector database that stores the embeddings of the chunks of the text made through chunking. 
- This helps storing and retrieval of data easier.


### Security and safety layer
Guardrails
- This is s framework that is used for security and safety purpoese.
- It checks that the input prompt given to the model should not be malicious or a prompt injection.
- This makes the system more secure and helps to maintain the decorum that is defined for that particular model.


### Evaluation 
DeepEval
- This is a framework used for testing and evaluation purposes, just to check that the things are working smoothly or not without creating errors.

## Knowledge base and dataset instructions

### Knowledge ingestion (data extraction)
- Source from which data or PDF is downloaded is provided.
- The pdf is named as seller_guide.pdf.

### Parsing and chunking of the data
- Data is extracted and then parsed.
- The whole data is then converted into small chunks with the process of chunking.

### Embedding process
- The chunks are then converted into embeddings(vector format of text).

### Vector Database
- These embeddings are then stored inside a vector database i.e, ChromaDB.

### Retriever
- These embeddings can be retrieved using a retriever.

## Files and folders description
### data folder
- Contains the data on which RAG technology is applied.
- The data is stored in a PDF format which is named as seller_guide.pdf.

### chroma_db folder
- This folder contains the vector database in which embeddings of all the chunks created are stored.

### src folder
- This folder is the heart of the project.
- This folder consists of multiple files i.e, 
1. agent.py
2. guradrails_config.py
3. database.py

### agent.py
- This file contains the agent that perform the main task and runs with the main() function.

### guardrails_config.py
- This file contains the whole configuration and settings of the guardrails applied on the agents and the whole project.
- Guardrails add a security and safety layer on the working of any project.
- This helps the system to stay secure and safe.

- Guardrails are of two types- 
1. Input guardrails- Ensures the input given should be filtered before executing it. In this, profanity and toxicity validators are used.
2. Output guardrails- In case after applying the input guardrails, still some conflicting output is getting generated, in that case output guardrails matter and prevent the system to give away the malicious generated output.

### database.py
- This file contains all the working of the RAG.
- The loading, splitting, chunking, and storing into vector database processes.

### tests folder
- This folder contains the files i.e, test_rag_metrics.py
- This file contains the code to measure how accurately RAG is working.
- This file also contains DeepEval test cases files(atleast 10) to check the working of the project.

Inside the tests folder, there are multiple files which are used to check multiple activies or processes.
1. test_agent.py - This code helps to check the working of the agent that either its working perfectly or not.

2. test_config.py - This file helps to check the configuration of the environment variables or other variables also.

3. test_database.py - This file helps to check the vector database.

4. test_rag_metrics.py - This file checks the accuracy of the RAG, that how it is carrying out multiple operations.

5. test_api_key.py - This file is responsible to check the that are api_key in set correctly or not.

6. test_pydantic.py - This file helps to check either the pydantic AI in the project works correctly.

7. test_database.py - This file checks that either the database is working properly or not.


### README.md
- This is the documentation file which consists of all the information about the project i.e, folder structure, files description, multiple commands needed to run the project, functional and non-functional requirements also.

### requirements.txt
- This file contains all the required packages that are needed to run the project.

### .venv
- This is the virtual environment file.
- Using this, a virtual environment is set up in which all the requirements are being installed.

### .env
- This file contains all the secret and confidential keys or data that needs to remain hidden and to be revealed anywhere.

## How to make virtual environemnt
- Run the command in cmd
"python -m venv .venv"

### Activate the virtual environment
- Run the command in cmd
".venv\Scripts\activate"

## How to install requirements
- Run the command in cmd
"pip install -r requirements.txt"

## How to run the project
- Run the command in cmd
"python -m src.agent"
